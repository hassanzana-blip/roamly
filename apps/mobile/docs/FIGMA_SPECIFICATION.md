# Editable HelloSky specification

[Figma file](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz).

This documents the implemented charcoal/white/HelloSky-blue direction. It is not a new concept and is not evidence of native iOS execution.

- [Home, results, details](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=22-151): three editable 393 × 852 frames based on app `dad15c4`, with 25 component instances and the bundled destination photography.
- [Airport, filters, dates](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=28-216): three editable companion frames based on existing picker/filter code. The filters explicitly use one isolated `SEK_OFFER` fixture. Native date controls are schematic and require iOS verification.
- [Empty and loading states](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=33-218): four editable StateView variants, dark/light and busy/idle, derived from `ui.tsx`. Title/body are required caller properties; body visibility and icon swapping are exposed. Native ActivityIndicator is schematic. Action buttons belong in the parent action wrapper, as in code.
- [Seller choice and baggage](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=37-490): four SellerOfferRow variants (selected/unselected, price right/below) match the reviewed `be41be4` implementation. Six baggage variants document included, excluded and unknown facts for cabin/checked bags. Title, Value and Icon are required caller properties, as in the native InfoRow; examples explicitly set them and never imply default baggage allowances.
- [Inline banners](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=39-375): six light/dark information, warning and error variants, with editable caller-provided messages, source icons and semantic colors. Actions remain separate. The dark error color is sourced from the existing `ui.tsx` literal, not invented as a new app theme value.
- [Results, filters, dates and airport · `6935d1d`](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=65-226) (P6): six editable 393 × 852 frames built from library instances – results with active-filter chips, sort tabs and compact cards; the range calendar sheet (9.–16. okt., «Søk på nytt»); the airport picker for «oslo» (OSL, then TRF as its own «Brukes også for Oslo-området» row); the filter sheet at «Utreise» (Avgang | Ankomst •) and at «Mellomlanding i»; and the empty answer with «Prøv datoene rundt». Every screen was compared side by side with a NON-NATIVE browser capture of the same state at 393 × 852; numbers are the demo fixture's, and the app labels that data DEMO. The keyboard, the iOS clear button and the browser's focus box are not drawn.
- New components for `6935d1d`: [OfferCard (compact)](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=62-508) (Trip = Return/One way; Airline, Price, Basis, Sellers, Risk and Next day properties), [SortTab](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=56-385), [FilterChip](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=57-376), [RecentSearchChip](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=57-381), [AirportRow](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=58-416) (Suggestion, Match, Exact code, Nearby) and [CalendarDay](https://www.figma.com/design/YE2XDmrOTFY8dRFiarPxSz?node-id=59-634) (seven roles), plus eight icons (close, clock, chevronRight, plane, moon, sun, sunrise, sunset). Leg texts on the card and the emphasised parts of a Match row are edited directly on the instance; the component descriptions say how.
- Library: 80 variables, 26 text styles, seventeen component families with 63 variants, sixteen SVG icon components, a destination card and two chips. Input placeholder is exposed as a text property. QA pass on 25.09.2026: no unbound fills or strokes, no unstyled text and no default layer names in the new components or in P6, apart from the three sheet scrims, which use the code literal `rgba(0, 0, 0, 0.5)`.
- Shared colors, spacing and native typography are sourced from `src/lib/theme.ts`. Figma uses a documented Inter fallback because its renderer returned unusable SF Pro text. The app retains iOS system typography; no Apple font files were downloaded or redistributed.
- Related content uses Auto Layout; panels are editable layers, not flattened screenshots. Safe-area space is shown without drawing device chrome.

The seller component documents the two adaptive price placements. In code, measured name wrapping or text-column width below 80 × fontScale moves the price below. Layout state survives tab changes and remeasures on fontScale changes. Figma does not execute those measurements. All new visible component fills/strokes are variable-bound; reviewed screenshots show no clipping. Value widths and baggage icon overrides were corrected after the first visual review.

Two Figma details worth knowing when editing: a colour variable bound to a fill does not carry that fill's own opacity into instances, so the card's track lines use layer opacity (28 %) instead; and a sheet's title row is 44 pt tall because «Ferdig» has a 44 pt target.

Still open: full large-text screen specimens, the filter sheet's stops, airline, price and leg-length sections as their own viewports, native keyboard/calendar/VoiceOver testing, photo-source attribution, and coherent prototype wiring. P4, P5 and P6 use different labelled fixtures, so they are not linked as though they form one stateful search.

Use the actual app's `DESIGN.md` and `docs/evidence/MANIFEST.md` for newer implementation changes and fixture provenance. P4 is a normal-text specimen of `dad15c4`, the seller and baggage boards describe `be41be4`, and P6 describes `6935d1d`. None of them proves native rendering.
